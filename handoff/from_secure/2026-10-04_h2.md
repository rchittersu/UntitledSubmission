# Handoff 2 — native-resolution protocol-v3 evaluation matrix — 2026-10-04

## TL;DR
- Native (~30 MP) test set (76 captures; indoor-37 + outdoor-39), val and train sets built from raw; protocol-v3 matrix run for 5 deblurrers x {native, x2, x4 pipelines} with bicubic / SwinIR(-real) / HAT-L / Real-HAT / OSEDiff upsamplers, plus 5 training-free fusion baselines (composite, multiscale, guided, detail, exemplar; parameters tuned on val only). 95% paired-bootstrap CIs everywhere.
- **Headline (indoor-37, tables below):** at the same native target, low-res deblur + plain bicubic x4 (PSNR 27.03 DRBNet / 27.03 Restormer) beats native-resolution inference of every baseline (25.2-25.9) by 1.1-1.8 dB, i.e. the resolution gap holds on the v2/v3 data. Native inference of the deblurrers is within -0.1..+0.6 dB of the blurry input (25.28) in PSNR (Restormer and LaKDNet slightly below it).
- Learned/generative upsamplers (SwinIR-real, Real-HAT, OSEDiff) *lose* PSNR vs bicubic (OSEDiff -1.2..-1.6 dB, dPSNR in the blurriest bin b0 negative) while improving some perceptual numbers; fusion "guided" is best on PSNR/SSIM (Restormer 27.08), "detail" best on DISTS/LPIPS (0.199 / 0.240) with -0.3 dB. Nothing training-free dominates on both axes — the room for the method is on the Pareto front, not on a single scalar.
- **Cut / not done:** DATSR reference-based SR (measured >15 min/image on one shared GPU; opt-in in `run_baselines_bd.sh`, not run). Sanity check "GPU-vs-CPU metric agreement" was NOT run (see Open).
- Code fixes in the patch (see Code state): exact attention-mask cache (SwinIR/HAT ~7-30x faster), hard failure when blur-map metrics lack DP maps, crash-tolerant `run_model`, subset tool, multi-node locks.

## What was done
- Hardware: two shared 8x80 GB GPU nodes plus one extra 8-GPU node used for CPU-only fusion; torch/CUDA per node image. Other users' jobs were running on the nodes at times (load, thread oversubscription capped via OMP/MKL=24) => **all timings are indicative only**; SwinIR/HAT runs before the mask-cache fix were additionally slow (580 s -> 80 s per image on 1 GPU after fix; the pipeline_time column mixes both).
- Data: official 1680x1120 DPDD PNGs + CR2 raws; native sets via `build_native_set.py` with per-capture calibration and **translation-only** registration (as decided outside). Local-vs-node builds differ slightly (indoor median residual 1.29 vs 1.34 px); outdoor calibration quality is lower than indoor. Flagged registration shifts > 10 px exist (worst 22.95 px, capture 1P0A1618); kept in all-76; no sensitivity run excluding them was done.
- Eval: `dpdd_eval_v3.yaml`, paper tiling (overlap = tile/8), metrics psnr/apsnr/ssim/hb/lpips/dists with DP blur-map bins b0-b3 (see docs/evaluation.md for bin definitions), `dpsnr_b0` = PSNR gain over the input in bin 0, multi-resolution (s4/s2/s1) scoring, CIs via `summarize.py --ci --ref`.
- Baselines: Restormer (DPDD), LaKDNet-L, DRBNet (single), IFAN (**public mirror weights, not the official release**), Bokehlicious; upsamplers bicubic, SwinIR-real x4/x2, HAT-L, Real-HAT, OSEDiff (needed a pinned old-library overlay, a patched BERT-tokenizer path and a clean-and-resume loop because workers segfault at teardown; outputs were verified to decode, 76/76 per pass, and the final evaluation was run in the normal environment).
- Fusion baselines tuned on the val set only, applied to Restormer and DRBNet x4 pipeline outputs.
- Final tables: all 76 and indoor-37 (a subset of the same runs, filtered by `subset_results.py`). Why indoor-37 is separate: it is the subset comparable to the P1/v1 numbers and to the indoor-only literature protocol; outdoor has weaker calibration.

## Decisions & findings
- **Verified:** x4 low-res deblur + bicubic beats all native inference (CIs exclude zero for every baseline on PSNR/SSIM; paired % images better < 25%). Perceptual metrics (DISTS/LPIPS) move the other way: native outputs stay close to the input (low LPIPS) because they barely change it.
- **Verified:** generative/real-SR upsamplers trade PSNR for perceptual realism; OSEDiff is the worst on PSNR and negative on dpsnr_b0 (hallucination in the blurriest regions) — supports the "blur-aware copy/generate" motivation.
- **Verified:** fusion baselines show a PSNR vs DISTS trade-off; none is Pareto-better than composite on all metrics. Strong, simple reference for the method.
- **Hypothesis:** the native-inference deficit is mostly tiling/receptive-field mismatch rather than registration (t512 vs paper tiling differ by <= 0.06 dB).
- Contradicts earlier P1 claims already retracted (homography registration, PSF matching); this run follows the outside decisions (translation registration, no PSF matching). D2 (Restormer reproduction) remains +0.03 dB off the published number, unresolved.
- Incident: a missing DP-map link silently dropped blur-bin metrics on the nodes in an early run; fixed, five pipelines re-evaluated, and `evaluate.py` now raises if blur-map metrics are requested without DP maps (test added). All 19 final steps verified complete.
