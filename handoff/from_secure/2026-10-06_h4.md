- Setup (secure env, no internet on the compute nodes): S3Diff / VOSR code and weights fetched on a connected machine and moved over (SD-Turbo 4.9 GB, S3Diff 0.13 GB, VOSR2 + Qwen VAE + SD2.1 VAE + DINOv2 hub cache 10 GB). - One environment: torch 2.8, diffusers 0.41 (dev), transformers 5.17, peft 0.20. `code/uhdd/adapters/compat.py` provides the shims: xformers and `torch.compile` off for VOSR (installed xformers wheel is for another torch; Triton cannot parse the node CUDA version); OSEDiff import / API aliases (partial, see Deviations).

- Launch: runs triggered by the user with `launch.sh` (GPUs: 80 GB class, 8 per node). S3Diff tile 192 / overlap 24; VOSR2 tile 128 / 16; Real-HAT 512 / 64; bicubic whole.
- Crash handling: a worker segfaulted at exit during a multi-GPU VOSR2 run (73/76 images written, `mp.spawn` killed the siblings). Fixes: the launcher sets `UHDD_FAST_EXIT=1`; resume now treats an output as done only if the PNG decodes. The run was resumed and completed (76/76).

- **Verified (numbers above):** at native resolution S3Diff trades PSNR for perceptual metrics: on `ours_x4` PSNR is 0.9-1.3 dB below bicubic and in-focus-bin gain (dpsnr_b0) is negative for the DRBNet anchor (-0.99), while LPIPS / DISTS / MUSIQ / CLIPIQA are the best of all upsamplers; VOSR2 stays close to bicubic in PSNR (-0.2 dB) with better LPIPS, MUSIQ, CLIPIQA.
- **Inputs check, finding, not a data fault:** official vs ours x4 **targets** have median PSNR 32.13 dB (min 17.52, 23 scenes below 30 dB), well below the ~39 dB calibration number (that number is measured before the target is registered to the input; the official targets are not registered). Tests I ran: removing a global residual translation moves the median only 32.1 -> 32.8 dB; a per-channel gain / offset fit changes nothing (32.2); global sharpness ratio ours/official 0.95. The difference is concentrated in fine detail (chain-link fence, bark) and correlates with our registration shift (Spearman -0.6, scenes under 30 dB have median shift 2.5 px vs 1.3 px). **Hypothesis**, not verified: sub-pixel / warp differences from registering the target plus different development of fine texture. The check on targets is now informational (inputs and names remain strict).
- Handoff-3 claim to keep in mind: the control run on the original images reproduces published numbers; our renderings shift per-model PSNR (see handoff 3).
